# Vhui USB Server — Windows-интерфейс

Версия 0.3.1 поставляется одним файлом `Vhui.Server.exe`: копируйте только его.
.NET и руководства встроены; устанавливать .NET отдельно не требуется.
Руководство открывается в окне **Справка → Руководство**. Настройки, язык и имена
устройств сохраняются как раньше в `%LOCALAPPDATA%\Vhui\Server\server.ini`.

Версия 0.3.0: меню **Language / Язык → English / Русский** переключает язык
сразу и сохраняет выбор. Руководство на английском: [GUI.en.md](GUI.en.md).

Выберите устройство и нажмите **Переименовать…** в панели, меню «Устройства» или
контекстном меню. Заданное имя отображается на сервере и передаётся штатному клиенту.
Оно сохраняется между запусками; устройство с серийным номером сохраняет имя
при смене USB-порта. При отсутствии серийного номера имя привязано к модели и порту.
Пустое имя или кнопка **Восстановить исходное** возвращают исходное название.
Имена поддерживают Unicode, максимум 63 байта UTF-8. Локальное переименование
в самом клиенте может иметь приоритет над именем сервера.
Переименование и смена языка не перезапускают сервер и не отключают USB.
Исходные USB-идентификаторы и описатели остаются прежними.
В INI язык хранится в `DesktopLanguage`, имена — в `DeviceAliases`.

Запустите `Vhui.Server.exe`. Папки старых сборок для этого EXE не нужны.

1. В дереве выберите USB-устройство и нажмите **Предоставить доступ**.
2. Нажмите **Запустить**. При необходимости Windows запросит права администратора
   для временной смены USB-драйвера.
3. В штатном клиенте VirtualHere укажите адрес этого компьютера и порт 7575.
   По умолчанию сервер доступен только на этом компьютере.
4. Для другого компьютера в **Настройки → Основные** укажите `0.0.0.0` вместо
   `127.0.0.1`. Обнаружение в сети можно включить там же.

Устройства изначально не предоставляются клиентам: разрешите доступ к нужным.
Настройка запоминается для модели, серийного номера и физического USB-порта.
После переноса в другой порт включите доступ ещё раз. Фильтры
AllowedDevices/IgnoredDevices в INI продолжают действовать.

В дереве показаны состояния устройств и IP клиента, который использует USB.
Кнопка **Отключить доступ** снимает устройство с публикации при следующем опросе
(обычно до двух секунд). Для используемого устройства запрашивается подтверждение.
**Остановить** завершает подключения и возвращает драйверы локальным устройствам.
Закрытие окна завершает сервер. **Вид → Свернуть в трей** оставляет его работающим;
двойной щелчок по значку возвращает окно.

В **Настройках** доступны имя сервера, IP/порт, разрешённые IP/CIDR, обнаружение,
TLS, сертификаты клиентов и обратные подключения. Пустой список IP или `*`
разрешает любые адреса; `192.168.0.190` разрешает один компьютер,
`192.168.0.0/24` — подсеть. Административные ограничения задаются отдельно.
Сохранение перезапускает работающий
сервер, поэтому текущие клиенты отключатся. Сертификат сервера включает режим
только TLS, обычно порт 7574.

Журнал расположен внизу окна; его можно скрыть, очистить или сохранить.
Меню **Сервер → Открыть файл настроек** доступно при остановленном сервере.
Настройки находятся в `%LOCALAPPDATA%\Vhui\Server\server.ini`.
Для отдельного файла: `Vhui.Server.exe --config C:\path\server.ini`.
Аргумент `--start` запускает сервер после открытия окна.

GUI использует тот же протокол и WinUSB backend, что `Vhui.Recovery.exe`.
Он управляет собственным сервером в процессе окна; установленная служба Windows
управляется отдельно через CLI. Два сервера не могут слушать один адрес/порт.
EasyFind и проверки лицензии отсутствуют.

Сборка из папки проекта: `powershell -File dotnet/Build.ps1 -Publish`.
Проверка окна: `powershell -File dotnet/scripts/Test-Gui.ps1`.
Она открывает настоящее окно, проверяет сохранение выбора, публикацию/снятие
устройства, сетевой ответ и остановку. Захват USB в этой проверке отключён,
драйверы не меняются. Снимки окна и результат: `dotnet/artifacts/gui-smoke/`.

В версии 0.2.1 исправлены потеря выбора при временно недоступном серийном номере
и зависание повторной публикации в «Подготовка…». Опрос USB не выполняется
одновременно со сменой драйвера. Для захваченного устройства используются
сохранённые описатели, при этом физическое подключение продолжает проверяться.
Ошибка чтения метаданных не меняет имя и идентичность уже известного устройства.
Появление ранее недоступного серийного номера не считается заменой USB-устройства.
При сбое фонового опроса сервер дожидается отмены передач и возврата драйверов.

Предупреждения об опросе теперь содержат номер порта и код ошибки. Ошибки других
портов не означают отказ выбранного устройства. Подтверждённое физическое
отключение по-прежнему снимает устройство с публикации.

Аппаратная проверка этой версии: камера Trust QHD Webcam, штатный клиент 6.0.3,
три цикла захвата, получения кадра, отключения доступа и повторного включения.
Все циклы успешны, штатный драйвер восстановлен. Результат:
`dotnet/artifacts/republish-client/result.json`. Для повторения запустите
`powershell -File dotnet/scripts/Test-RepublishClient.ps1`; скрипт сам запрашивает
повышение прав через оболочку Windows.
